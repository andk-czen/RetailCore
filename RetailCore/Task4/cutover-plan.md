# Cutover plan

## Цель переключения 
Перевести операции сопровождения клиентов по получению данных о заказе (статус и история) на новую модель, без изменения заказа и без остановки прочих процессов. Проверить корректность и целостность данных, производительность системы и стабильность нового контура.


## Условия запуска 
| Условие | Как проверяем | Ожидаемое состояние | Ответственный |
|---|---|---|:---:|
| Границы определены и технологическое окно предоставлено | Подтверждение от Product Owner | Записаны параметры пилота, PO подтвердил окно и риски   | *Product Owner* |
| Готовность модели  | Консоль управления флагами | Флаг готов к включению | *DevOps* |
| Консистентность данных |Сверка выгрузок и отчетов | Расхождения ≤1% записей | *DBA* |
| Наличие алертов и дашбордов | Проверка дашбордов и правил алертов | Все алерты настроены и работают | *SRE Lead* |
| Инструкции поддержки готовы | Проверка базы знаний и чек‑листов | Инструкции актуальны и опубликованы |  *Support Lead* |
| Нет критических инцидентов за последние сутки | Управление инцидентами | Отсутствие критических инцидентов  | *DevOps, инфраструктура* |
| План отката сформирован, откат успешно протестирован | Протокол испытаний  | Есть подтвержденные результаты тестов | *SRE Lead* |
| Выделены дополнительные ресурсы на сопровождение | Письменные договоренности с руководством | Предоставлены ресурсы, ключевые сотрудники поставлены в известность, доступны, готовы к повышенной нагрузке |*SRE Lead, DevOps, инфраструктура*|


## Роли и ответственность 

| Роль | Ответственность|
|---|---|
| Техлид | Принимает go, hold, rollback и завершение. Единолично запускает откат при достижении порога |
| Координатор переключения | Ведёт runbook, время и журнал решений. Останавливает выполнение следующего шага |
| Архитектор | Подтверждает соответствие целевой схеме и полноту rollback. Блокирует запуск при нарушении границ |
| Техлид | Отвечает за старый API, Oracle-семантику и карту статусов. Подтверждает источник истины |
| Разработчик сервиса | Проверяет загрузку, потребление событий и API. Исправляет новый контур и запускает безопасный replay |
| DBA | Определяет точку отсечения и контролирует выгрузку и нагрузку Oracle. Останавливает загрузку при риске для Oracle |
| Инженер эксплуатации | Следит за метриками, логами, очередью и ресурсами. Объявляет технический no-go |
| Представитель поддержки | Выполняет пользовательские проверки. Блокирует расширение при неверном статусе или истории |
| Бизнес-владелец процесса заказов | Согласует допустимый риск и результат пилота. Подтверждает продолжение после наблюдения |


## Пошаговый сценарий 
| Шаг | Действие | Ответственный | Ожидаемый результат |
|---|---|:---:|---|---|
| 1. | Выполнить подготовительные действия, проверить состав участников и канал связи | *Техлид* | Участники на связи, журнал запущен |
| 2. | Подтвердить отсутствие критичных инцидентов | *Эксплуатация* | Критических инцидентов нет |
| 3. | Проверить дашборд, оповещения, логи и доступ к rollback | *Эксплуатация* | Все сигналы и управление доступны |
| 4. | Зафиксировать точку сверки и сравнить последние состояния | *DBA, техлид* | Критичных расхождений нет |
| 5. | Проверить задержку событий, очередь и DLQ | *Разработчик* | Проекция актуальна |
| 6. | Выполнить smoke-тест старого и нового API на контрольных заказах | *Разработчики, поддержка* | Ответы корректны, старый API работает, новый API работает |
| 7. | Включить теневое контрольное сравнение для согласованной области | *Техлид* | Пользователь получает старый ответ, результаты сравниваются |
| 8. | Оценить расхождения контрольного сравнения | *Техлид, поддержка* | Расхождений нет или они в допустимых пределах |
| 9. | Переключить внутреннюю тестовую группу поддержки | *Техлид* | Запросы группы идут в новый сервис |
| 10. | Проверить контрольные заказы, ошибки, задержку и обращения | *Все участвующие роли* | Условий остановки нет |
| 11. | Переключить согласованную пилотную группу поддержки | *Техлид* | Новый контур обслуживает пилот |
| 12. | Повторить техническую и пользовательскую проверку | *Эксплуатация, поддержка* | Показатели в допустимых пределах |
| 13. | Принять решение об окончательном переключении или откате | *Техлид* | Решение записано в журнале |
| 14. | После согласованного наблюдения | Переключить оставшуюся поддержку или завершить пилот | *Техлид* | Достигнута утверждённая область cutover |


## Проверки после переключения 
- запросы выбранной группы действительно идут в новый сервис
- старый путь остаётся доступным
- задержка событий и глубина очереди не растут 
- не выявлено неизвестных статусов
- нагрузка Oracle остается в допустимых пределах
- исторический заказ и новый заказ читаются одинаково
- поддержка понимает внешний статус
- поддержка видит свежие актуальные данные
- контрольные тестовые заказы выполнены по стандартному сценарию


## Rollback-сценарий 

| Шаг | Действие | Ответственный | Ожидаемый результат |
|---|---|:---:|---|
| 1. | Объявить rollback и остановить расширение | *Техлид* | Новые группы не переключаются |
| 2. | Зафиксировать время, область и список затронутых запросов и заказов | *Техлид* | Есть границы последующей сверки |
| 3. | Переключить маршрутизацию всей пилотной группы на старый API | *Техлид* | Поддержка снова читает монолит/Oracle |
| 4. | Выполнить smoke-тест старого пути | *Техлид, поддержка* | Старое чтение работает корректно |
| 5. | Сообщить поддержке о возврате и известных расхождениях | *Поддержка* | Операторы используют старый источник |
| 6. | Оставить потребление событий включённым, если оно не влияет на Oracle и заказ | *Разработчик* | Сохраняются данные для диагностики |
| 7. | Если потребление создаёт риск, остановить потребителя без изменения монолита | *Эксплуатация* | Критический путь заказа не затронут |
| 8. | Сверить заказы из списка, исправить модель или карту статусов | *Команды заказов и сервиса* | Причина локализована |
| 9. | Повторно проиграть события идемпотентно и повторить сверку | *Разработчик* | Проекция восстановлена |
| 10. | Оформить решение о новой попытке или переносе | *Техлид* | Следующее действие согласовано |
